## 2. WHAT WAS SETTLED (measured, not argued)

- **FEX cannot run 32-bit OpenGL.** `SetPixelFormat` fails on **0 of 320** formats; the same
  source built 64-bit gets 320/320 under FEX, and 32-bit gets 320/320 under Box64. So the whole
  id Tech 4 family is Box64-only. Upstream issue: FEX-Emu/FEX#4645. Ruled out: missing thunk (it
  is loaded), missing entry point, format choice, new WoW64, and FEX's own `GL:0` workaround.
- **Box64 bug #3** — `NtCreateFile` `FILE_CREATE` collision faults and the caught fault *replaces*
  the status, so the app gets `ERROR_NOACCESS` instead of `ERROR_FILE_EXISTS`. 100% reproducible,
  32-bit only, stock and patched alike.
- **Box64 bug #4** — `FINCSTP`/`FDECSTP` move TOP without rotating the stack-relative tag array.
  Same root defect as the FSAVE issue but **not covered by that fix**.
- **FEX bug** — in 32-bit code with a `.data` section, the instruction before a
  `mov %eax, moffs32` (`a3`) executes **twice**. `shr $11` shifts by 22, `inc` adds 2. **Never
  give a freestanding probe a `.data` section.**
- **`game-run.sh` leaked its GPU sampler on every run**, including dry runs — 19 orphans,
  206 process-hours, and the 14 phantom directories. Fixed.
- **The mouse's DirectInput path is faithful** — 40,171 px vs the X server's 40,233 raw, 0.15%
  apart, no spurious motion at rest, no overflow, no clamping.
- **DGX Spark is a fixed platform**, so a result here applies to every DGX Spark. Detect it with
  DMI `product_family` (reads `DGX Spark` even on an HP box). See `docs/SPARK-PLATFORM.md`.
